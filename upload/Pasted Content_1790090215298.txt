# MASTER ENGINEERING PROMPT

## Professional School Timetable Management & Automatic Scheduling System

You are a **Principal Software Architect, Senior Full-Stack Engineer, Constraint Programming Engineer, Database Architect, QA Engineer, and UI/UX Engineer**.

Your task is to **design and build a production-ready school timetable management and automatic scheduling platform**, inspired by the workflow, usability, flexibility, and scheduling capabilities of professional timetable software such as **aSc Timetables**.

This is NOT a demo, prototype, landing page, static dashboard, or fake scheduling interface.

Build a real application with:

* Real database
* Real authentication
* Real CRUD operations
* Real scheduling engine
* Real constraint validation
* Real automatic conflict resolution
* Real drag-and-drop timetable editing
* Real Excel export/import
* Real reports
* Real printing
* Real audit/history
* Real tests
* Production-quality architecture

The system must support Arabic RTL as the primary language and English as a secondary language.

# 18. HARD CONSTRAINTS

The following must never be violated.

## Teacher conflict

One teacher cannot teach two lessons simultaneously.

## Class conflict

One class cannot have two lessons simultaneously.

## Room conflict

One room cannot be used by two lessons simultaneously.

## Teacher availability

Do not schedule a teacher in forbidden slots.

## Teacher day off

Do not schedule teaching or duties on a teacher's day off unless explicitly overridden.

## Required weekly lessons

All required lessons must be scheduled.

## Room compatibility

Laboratory lessons must use compatible rooms.

## Capacity

Room capacity must support the class.

## Duty conflict

A teacher cannot teach while assigned to a duty.

## Fixed lessons

A fixed lesson cannot be moved automatically unless the administrator explicitly allows it.

# 21. SCHEDULING ALGORITHM

Use OR-Tools CP-SAT.

Represent each lesson occurrence as a scheduling variable.

Conceptually:

```text
X(lesson, day, period, room)
```

where:

```text
X = 1
```

means the lesson occupies that slot.

Add constraints for:

* teacher
* class
* room
* availability
* workload
* duties
* rooms
* fixed lessons
* consecutive lessons
* weekly occurrence count

Then create an optimization objective.

Example:

```text
Minimize(
    teacher_gaps * weight
    +
    subject_clustering * weight
    +
    seventh_period_deviation * weight
    +
    unwanted_slots * weight
)
```

# 64. IMPORTANT ENGINEERING RULES

Follow these rules throughout development:

1. Do not create fake functionality.
2. Do not hardcode business data.
3. Do not put scheduling logic inside React components.
4. Do not put solver logic inside API controllers.
5. Keep the solver independently testable.
6. Keep database models normalized.
7. Use transactions for important operations.
8. Validate data on backend and frontend.
9. Never trust client-side conflict validation.
10. Every manual timetable modification must be validated server-side.
11. Preserve timetable versions.
12. Do not regenerate the entire timetable for a simple manual move unless necessary.
13. Prefer incremental repair.
14. Explain solver failures.
15. Keep the system extensible.
16. Write tests while implementing features.
17. Never leave TODO placeholders for core functionality.
18. Never claim a feature works until it has been tested.

9. Produce the implementation roadmap.

After each phase:

1. Run tests.
2. Fix errors.
3. Verify database integrity.
4. Verify APIs.
5. Verify UI.
6. Report exactly what was implemented.
7. Report what remains.
8. Continue to the next phase only after the current phase is stable.

Do not skip phases.
